# Istruzioni del progetto

## Comportamento generale

- Non modificare il codice se non viene richiesto esplicitamente.
- Non effettuare refactoring, semplificazioni, modernizzazioni, riformattazioni o miglioramenti indipendenti di tua iniziativa.
- Se una modifica richiesta rende tecnicamente necessarie modifiche in altri punti del codice, tali modifiche collegate sono consentite.
- Se individui altri problemi o possibili miglioramenti, segnalali senza applicarli, salvo esplicita autorizzazione.
- Quando viene richiesta una revisione generale, analizza prima il codice e indica cosa potrebbe essere modificato. Non modificare i file finché non viene richiesto.
- Mantieni invariati stile, indentazione, spaziatura, righe vuote e disposizione del codice, salvo esplicita richiesta.

## PHP

- Preferisci la sintassi alternativa PHP dove supportata:
  - if(...): endif;
  - for(...): endfor;
  - foreach(...): endforeach;
  - switch(...): endswitch;
- Per try/catch usa invece la normale sintassi con parentesi graffe.

## SQL

- Scrivi tutte le istruzioni, funzioni e parole chiave SQL in minuscolo.

## Ambito delle modifiche

Applica esclusivamente le modifiche necessarie per soddisfare la richiesta specifica.

Non introdurre miglioramenti indipendenti solo perché il codice potrebbe risultare più pulito, elegante o conforme a pratiche comuni.

Se una parte del codice è scritta in modo non convenzionale, non modificarla automaticamente: potrebbe essere una scelta intenzionale legata al progetto.
