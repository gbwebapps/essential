AuthModel

class AuthModel extends BackendModel

Modello principale dedicato all'Autenticazione e alla Sicurezza degli accessi (Auth).

Estende il BackendModel e incapsula tutta la complessa business logic legata all'ingresso nel sistema. Gestisce il flusso di Login a più step (incluso il controllo 2FA), il sistema anti brute-force (throttling dei tentativi falliti), il recupero delle credenziali, la generazione di token crittografici (sessioni o cookie "Remember Me") e la tracciatura rigorosa di ogni accesso o disconnessione nell'Audit Log.

array login(array $posts, IncomingRequest $request)

Orchestratore principale del flusso di Autenticazione (Login).

Metodo denso e protetto:

  1. Filtra i dati in ingresso e legge le configurazioni (es. limiti tentativi, 2FA).
  2. Applica il throttling uniforme per email anonimizzata e indirizzo IP, anche per account inesistenti.
  3. Estrae l'utente verificando subito gli scudi (deve essere attivo, non cestinato, non sospeso).
  4. Valida l'hash della password con costo uniforme. Se fallisce, registra il tentativo errato a DB in transazione.
  5. Se la password è corretta ma il 2FA è attivo, parcheggia i dati sicuri in una sessione temporanea server-side, invia l'eventuale OTP via email e avvisa il controller di richiedere il secondo fattore (result => '2fa_required').
  6. Se il 2FA non è richiesto, azzera i tentativi falliti e demanda la creazione della sessione a innerLogin().

Parameters

array $posts

Credenziali pulite sottomesse dal form
IncomingRequest $request

Richiesta per estrarre Indirizzo IP

Return Value

array

Risposta strutturata con esito e messaggi per il router o il client

array verify(array $posts, IncomingRequest $request)

Convalida l'inserimento del codice OTP (Autenticazione a Due Fattori).

Estrae in sicurezza i dati pre-autorizzati dalla sessione temporanea auth_2fa_pending. Applica il Throttling specifico per il 2FA: se si sbaglia il codice troppe volte, rinnova il blocco e respinge. Verifica il codice immesso valutando sia la corrispondenza (Tramite App Authenticator o DB per OTP Email) sia la scadenza temporale. In caso di errore, incrementa i fallimenti in transazione. In caso di successo, svuota le tabelle temporanee, distrugge la sessione di parcheggio e finalizza l'ingresso invocando innerLogin().

Parameters

array $posts

Il payload contenente il codice (OTP)
IncomingRequest $request

Richiesta HTTP per l'estrazione dell'IP

Return Value

array

Esito dell'operazione (successo o messaggio d'errore specifico se scaduto o errato)

void logoutBySession(string $reason = 'manual')

Esegue il Logout (Disconnessione) per gli utenti autenticati via Sessione standard.

Recupera il token dalla sessione locale, identifica il log aperto nella tabella admins_logs (tramite login_log_id salvato durante il login) e lo chiude formalmente inserendo l'ora di uscita (last_activity) e la causale (es. 'manual' o 'timeout'). Infine distrugge il record del token dal database e resetta completamente la sessione PHP locale.

Parameters

string $reason

Motivo della disconnessione (default: 'manual')

Return Value

void

void logoutByCookie(string $cookieValue, string $reason = 'manual')

Esegue il Logout (Disconnessione) per gli utenti autenticati via Cookie "Ricordami".

Funzionamento analogo a logoutBySession, ma estrae l'hash partendo dal valore crittografato del cookie inviato dal browser. Chiude il log aperto registrando il timestamp di logout ed elimina definitivamente il token di tipo 'cookie' dal database, invalidando gli accessi futuri.
